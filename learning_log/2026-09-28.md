## strategy_learner: rejected (no improvement)

candidate win rate 92.16% vs current 92.65%

Reasoning given: **Change summary** – The `deficit` function assumes the column can deal damage for only the number of rounds the current front pirate has before reaching position 3 (`steps = MAX_POSITION - front.position`). This is too pessimistic when there are several pirates stacked: if we kill the front early we can keep shooting the column for as many rounds as the *farthest‑back* pirate needs to reach 3. I replace the “steps” value with the maximum remaining steps among all pirates in the column, giving a tighter (optimistic) estimate of how much damage we can still inflict. This lets the policy recognise columns that are actually killable and avoids discarding useful merges or spawns.
