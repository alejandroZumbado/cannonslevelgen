## strategy_learner: rejected (no improvement)

candidate win rate 81.73% vs current 81.73%

Reasoning given: **Change explanation**  
The champion simulates the current round twice: it first applies damage and advances manually (building `pir`), then calls `simulate_round(new_cann, pirates)` which repeats the same damage‑and‑advance on the original pirate list. This double‑application inflates the “deficit” and future‑look‑ahead values, causing the policy to undervalue actions that actually keep the game safe (e.g., killing a position‑2 pirate). The fix is to use the already‑updated state (`pir` and `new_cann`) for the post‑round metrics instead of re‑simulating the round.
